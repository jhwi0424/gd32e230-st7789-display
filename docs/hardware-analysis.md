# 原固件与管脚分析

## 从 SWD 到接线结论

DAPLink 是调试访问通道，本次读取的是寄存器和 Flash 字节，不是板子自动提供的原理图或管脚清单。

1. 通过 CMSIS-DAP v2/WinUSB 连通 SWD，以 100 kHz 读取 DPIDR、CPUID、容量和向量表。
2. 从 0x08000000 读取完整 65536 字节 Flash，保留原文件并计算 SHA-256。
3. 按 Thumb 指令反汇编，从 0x08002404 显示初始化函数定位命令序列。
4. 追踪命令/数据函数里的 GPIO 写入、复位、片选及 SPI 复用配置。
5. 对照 GD32 寄存器定义和 ST7789 命令，推断信号用途。
6. 在 RAM 中运行图案，以实物显示和作者反馈验证整套方案。

## 函数与 GPIO 证据

以下地址只对应上述原固件。Thumb 调用指针最低位置 1，例如入口 0x08001824 对应指针 0x08001825。

| 观察位置 | 程序行为 | 分析结论 |
|---|---|---|
| 0x08001824 命令函数，0x0800184c 常量 | 向 0x48000428 写 0x10，再调用 SPI 发送 | PB4 拉低，DC 命令 |
| 0x08001850 数据函数，0x08001878 常量 | 向 0x48000418 写 0x10，再调用 SPI 发送 | PB4 拉高，DC 数据 |
| 0x0800187c 常量 | SPI 基址 0x40013000 | 使用 SPI0 |
| 0x0800267c 复位函数 | 通过 0x48000018/28 对 0x1000 做高—低—高操作 | PA12，屏幕 RESET |
| 0x080026b4 窗口函数，0x08002744/2748 常量 | 对 0x8000 做清零/置位，期间发送 0x2a、0x2b、0x2c | PA15，低有效片选 |
| 0x08000f08 后段 | 初始化后置位 GPIOA 的 0x0800 | PA11，高有效背光 |
| 0x08002c14 起 SPI 配置 | GPIOB 掩码 0x28，即 PB3/PB5，复用选择 0 | SPI0 SCK/MOSI 的引脚线索 |
| 0x08002404 起 GPIO 配置 | PA0–PA7 设为输出 | 只能确认配置，不能直接认定接往 DB0–DB7 |
| 同一初始化中 | PF6、PF7 输出，分别低、高 | 用途未证实，不能命名为供电使能或 WR/RD |

GPIOA=0x48000000、GPIOB=0x48000400、GPIOF=0x48001400。偏移 0x18 为原子置位/清零寄存器，偏移 0x28 为清零寄存器。上表相关置位操作使用低 16 位。

未逐条做导通测量，所以 GPIO 表是程序行为和整套点亮实验支持的映射，不是完整 PCB 网表。候选并口读取曾返回重复 0x04，没有得到有效 LCD ID，不能视为并口正确的证据。

## 原程序 SPI 参数

| 寄存器 | 运行中读取值 |
|---|---|
| SPI0_CTL0，0x40013000 | 0x0000c34e |
| SPI0_CTL1，0x40013004 | 0x00000002 |

CTL0 中 CKPL=1、CKPH=0，即时钟空闲高、第一跳变采样，常用命名是 SPI mode 2；原程序使用单线发送。

初期软件 SPI 空闲电平与原程序不同，但仅凭此差异不能认定它是唯一未出图原因。最终成功方案调用原固件发送函数，并重新初始化 LCD，保留实际可用的 GPIO、SPI 和时钟组合。

## 初始化参数与移植差异

| 0xc0 | 2c | 沿用 |

## 已点亮 RAM 程序

- 链接地址 0x20001000，保留原程序低地址 SRAM 状态；初始 SP 为 0x20002000。
- 命令调用指针 0x08001825，数据调用指针 0x08001851。
- 原程序先建立时钟与 SPI；RAM 程序随后禁止中断，用 SysTick 轮询延时重新初始化 LCD。
- 状态 0x20001e00：STAR=0x53544152、INIT=0x494e4954、PASS=0x50415353、FAULT=0x4641554c。
- 已发送行数放在 0x20001e04，完成后为 240。
- 图案逐像素计算，不建立完整帧缓冲。
- 完成后把 PA15 和 PA11 拉高，保留显示。
- 复现脚本先校验整个原 Flash；不匹配时停止，不能直接调用另一固件的同地址函数。
